# 開発者向け情報

## 構成

| パス | 役割 |
|---|---|
| `main.py` | Bot生成、Cog自動ロード、コマンド同期、ホットロード、ログ設定 |
| `cogs/auto_role.py` | 新規メンバーへのロール付与 |
| `cogs/role_manager.py` | `/myrole` と専用ロールデータ管理 |
| `cogs/private_vc/vc_main.py` | VC作成、削除、ポータル、スラッシュコマンド |
| `cogs/private_vc/views.py` | モーダル、ポータル、VC操作ボタン |
| `cogs/private_vc/utils.py` | VCデータの読み書きと状態Embed生成 |
| `data/` | JSON形式の永続データ |

## Cogの追加

`cogs/` 直下に `.py` を置くと自動ロード対象になります。サブフォルダーの場合は、現在の自動検出仕様では `vc_main.py` または `main.py` がエントリーポイントです。各Cogには次の形式の `setup` が必要です。

```python
async def setup(bot):
    await bot.add_cog(MyCog(bot))
```

## 変更の確認

```powershell
python -m compileall main.py cogs
```

起動中に `cogs/` のPythonファイルを変更すると自動再ロードされます。データ形式や権限設定を変更する場合は、Botを停止してバックアップを取ってから確認してください。

## 実装上の前提

- Discordのロール階層とチャンネル権限が最終的な操作可否を決めます
- JSON保存は単一プロセスでの運用を前提としています
- VCのボタンViewはBot再起動時に保存データから再登録されます
- `yt-dlp` と `PyNaCl` は現在のコード上で直接利用していませんが、依存一覧に含まれています
